01 · QUICK START

从克隆到第一条任务

不需要构建网站，也不需要安装项目依赖。准备好 OpenCode 和可用模型后，按顺序完成四步。

启动清单 0 / 4
  1. STEP 01

    克隆工程

    把编排配置、状态协议和教学网站一起拉到本地。

    git clone git@github.com:texfu1112-cloud/agent_flow.git
    cd agent_flow
  2. STEP 02

    在项目根目录启动 OpenCode

    先按 OpenCode 官方文档 完成安装。本工程最近使用 opencode-ai@1.18.18 验证。

    opencode

    配置、Agent、命令和插件不会热更新；修改后请退出并重启客户端。

  3. STEP 03

    连接模型 Provider

    在 OpenCode 中运行 /connect，确保账号能访问 Flash 与 Sol 两条模型路由。

    opencode/deepseek-v4.1-flash openai/gpt-5.6-sol

    如果你的 Provider 不同，只替换模型 ID；角色协议与状态格式无需改变。

  4. STEP 04

    把完整目标交给 Builder

    描述结果、约束和验收方式。Builder 会自己判断是否需要搜索、架构、计划与审查。

    /work 做一个响应式登录页，沿用现有视觉风格，并运行相关检查

02 · THE CREW

五个角色，只做自己擅长的事

Builder 是唯一写入者。其他角色在独立 child session 中返回小而明确的结果，不把搜索轨迹塞回主会话。

01 Builder 控制 · 实现 · 验证 PRIMARY 02 Explore 只读搜索 · 证据压缩 FLASH 03 Architect 长期决策 · 约束 SOL 04 Planner 拆解 · 风险 · 验证 SOL 05 Reviewer 审 Diff · 找缺口 SOL

DEFAULT AGENT · FLASH / MAX

Builder 是控制面，也是唯一的施工方。

它读取任务状态、决定要不要委派、修改代码、运行验证、处理 Review 反馈，最后把可恢复的检查点写回磁盘。

READ ONLY · FLASH / MAX

当实现位置未知时，它可以广搜仓库，但只返回路径、符号、事实和未知项。原始搜索日志不会占据昂贵模型的上下文。

DECISION GATE · SOL / MAX

Architect 只处理难以回头的选择。

新子系统、公共契约、持久化 Schema、安全边界、基础设施或跨模块重构才会触发。它读取精选上下文，不扫描整个仓库。

何时进入
高影响、长期、难逆决策
不可以做
编辑、构建、广泛搜索
核心产物
决定、约束与备选取舍

PLANNING GATE · SOL / MAX

Planner 把已知事实变成可执行顺序。

跨组件、迁移、风险修复、验收模糊或测试策略复杂时才调用。小而明确的本地改动由 Builder 直接写短计划。

何时进入
非平凡或高风险工作
关注内容
顺序、边界、回滚、验证
核心产物
实现级步骤与测试映射

REVIEW GATE · SOL / MAX

Reviewer 只审这次改动，不重读整个世界。

它从验收条件、Diff 和测试证据出发，优先发现正确性、安全、数据、并发和架构漂移问题；反馈由 Builder 修复。

何时进入
有意义的运行时或基础设施改动
可跳过
纯文案、格式或生成物
核心产物
按严重度排序的 Findings

03 · THE ROUTE

一条任务，六个可控阶段

不是每次都调用所有 Agent。门控让简单任务保持轻量，让高风险任务得到足够推理。

  1. 01

    FRAME

    把目标写成检查点

    Builder 把目标、验收条件、限制和当前阶段写入 TASK.md。

    Builder
  2. 02

    EXPLORE

    只在未知处搜索

    实现位置不清楚时，Explore 返回带路径证据的胶囊；已知位置则直接继续。

    Conditional
  3. 03

    GATE

    决定是否需要深度判断

    长期技术选择交给 Architect；非平凡执行顺序交给 Planner。

    Sol gate
  4. 04

    BUILD

    做最小且正确的改动

    Builder 遵循现有约定，保护无关工作，并实时更新任务清单。

    Builder
  5. 05

    VERIFY + REVIEW

    先窄测，再审关键风险

    从最相关检查开始；有意义的代码或基础设施改动进入 Reviewer 修复循环。

    Evidence
  6. 06

    CLOSE

    让下一次打开就能继续

    记录状态、变更、验证、阻塞和唯一下一步，再给用户简洁结果。

    TASK.md
A

ARCHITECTURE GATE

什么时候要 Architect？

公共接口、持久化数据、安全边界、依赖或基础设施、跨模块重构，以及任何难以回滚的决定。

否则：Builder 自己决策
P

PLANNING GATE

什么时候要 Planner？

跨组件行为、迁移、风险修复、验收不清或需要认真设计测试策略的任务。

否则：TASK.md 中写短计划
R

REVIEW GATE

什么时候要 Reviewer？

运行时行为、API、数据、安全、并发、基础设施或其他有实际风险的改动。

仅纯文案 / 格式可跳过

04 · COMMAND DECK

记住三条命令就够了

命令不是三个独立机器人，而是三个进入 Builder 工作流的清晰入口。

01START

/work

开始一项完整工作。你的描述会成为权威需求，Builder 从 Frame 一直负责到 Close。

/work 给设置页增加主题切换，保留现有偏好，并补相关测试

最好同时说清楚：结果、不能破坏什么、怎样算完成。

02SAVE

/checkpoint

准备结束或切换会话时，要求 Builder 清理并持久化可恢复的任务状态，不开始新工作。

/checkpoint 准备切换会话

它会留下状态、已完成项、验证、阻塞和一个准确的下一步。

03RESUME

/continue-task

在全新会话中只依赖磁盘状态恢复，先验证记录是否仍与工作树一致，再从 Next Action 继续。

/continue-task

/resume 是 OpenCode 原生会话列表，因此这里刻意使用不同名字。

05 · DURABLE MEMORY

磁盘状态，比聊天记录更可信

聊天会被压缩、会过期。这个工程把真正需要跨会话保留的信息分层写入版本化文件。

SOURCE OF TRUTH从高到低
  1. 01
    当前源码 + 验证结果真实行为永远第一
  2. 02
    ARCHITECTURE + DECISIONS已接受的长期边界
  3. 03
    TASK.md当前任务检查点
  4. 04
    CONTEXT.md可替换的证据胶囊
  5. 05
    聊天历史最低优先级

发现冲突？报告并修正旧状态，而不是盲从旧摘要。

TASK.md

一项任务一份可恢复检查点。目标、验收、阶段、进度、验证、阻塞和唯一下一步都在这里。

ARCHITECTURE.md

预算 · 约 4,000 tokens

DECISIONS.md

格式 · 简洁 ADR，最新优先

STATEFUL COMPACTION

压缩发生时，最新任务检查点会被重新注入。

插件在 experimental.session.compacting 钩子中读取 TASK.md， 把目标、进度、验证和下一步带进压缩后的上下文。超过 12,000 字符时会截断并要求重新读取文件。

TASK.md 缺失时插件静默跳过，不会让压缩流程失败。

06 · PLAYBOOKS

照着这四种场景开始

好的请求描述结果和边界，而不是替 Builder 预先决定每一步。

01
开发一个完整功能会经过 Explore / Plan / Review 的典型任务
+

告诉 Builder 用户价值、关键约束和验收条件。不要一次粘贴整个仓库。

/work 为后台增加审计日志列表。沿用现有权限模型，支持按操作者和日期筛选，补 API 与 UI 测试，不修改日志写入格式。
02

+

本地改动很明确时，Builder 会在 TASK 中写短计划后直接实现，仍然会做最相关验证。

/work 把 README 中的旧命令名称改为 /continue-task，只改文档并检查所有引用
03
跨会话继续复杂任务不依赖上一段聊天历史
+

先让当前会话落盘，再开干净会话。新 Builder 会校验工作树，然后从唯一 Next Action 继续。

/checkpoint→/new→/continue-task
04

+

让 Explore 找到真实命令和稳定边界，但不要把整个仓库摘要塞进架构文件。

常见问题

我改了 Agent 或命令，为什么 OpenCode 没变化？+

这些文件只在启动时加载。完全退出 OpenCode，从项目根目录重新启动，再运行 opencode debug config。

账号访问不到配置里的模型怎么办？+

先用 /connect 配置 Provider；如模型 ID 不同，只修改 opencode.json 与 .opencode/agents/*.md 中的 provider/model ID。

什么时候应该开一个新会话？+

一个主会话原则上只做一项任务。任务需要换上下文时用 checkpoint 流程；完全无关的新任务，先结束或检查点当前任务，再开新会话。

CONTEXT.md 和源码冲突时相信谁？+

相信当前源码与验证结果。修正陈旧的胶囊，再继续工作；聊天历史的优先级最低。
